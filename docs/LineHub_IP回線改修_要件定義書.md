# LineHub — IP回線管理 改修　要件定義書

**作成日：** 2026年7月10日  
**ステータス：** 確定版（SF商品コード・計算ルール確定済み）  
**対象システム：** LineHub（IP・携帯回線 統合管理システム）  
**リポジトリ：** https://github.com/ryujikawakami-jpg/lime-management

---

## 1. 目的

既存のIP回線管理（Phase 1実装分）を全面刷新する。  
通話明細CSV（CDR）を取り込み、通話種別ごとのタリフ計算で取引先ごとの通話料を自動集計し、Salesforceへボタン一つで登録する。  
運用が定着している**携帯回線管理と同じ画面構成・操作感**に統一する。

---

## 2. 現状と課題

### 現状（Phase 1実装分）

- AdjustOne / ProDelight CSVの取込
- パック管理・超過料金計算
- 請求アカウント・チャンネルグループ・電話番号の管理

### 課題

- 現行の集計方式が実際の運用（CDRベースの通話料計算）と合っていない
- IP回線と携帯回線で画面構成・文言が異なり、操作を覚え直す必要がある
- タリフ（単価）を取引先ごとに調整する仕組みがない

---

## 3. 新フロー（目指す姿）

```
CDR CSV（月に6ファイル程度）をインポート画面からアップロード
  → 通話種別を4パターンに自動分類
  → タリフ（取引先別 or デフォルト）で通話料を自動計算
  → 番号マスタ（表番号・裏番号）で取引先を自動紐付け
  → LineHub上で内容確認
  → ボタン一つでSalesforceに2商品で登録
```

## 6. CDR CSVファイル仕様

### 基本情報

| 項目 | 内容 |
|---|---|
| ファイル名規則 | `cdr_{請求アカウント}_{利用月YYYYMM}.csv`（例：`cdr_K202206009_202605.csv`） |
| 文字コード | **Shift-JIS**（取込時にUTF-8へ変換） |
| ファイル構成 | 1ファイル = 1請求アカウント |
| 投入頻度 | **差分投入・月に6ファイル程度** |
| 明細粒度 | 1通話 = 1行 |
| ヘッダー行 | 1行目のみ |

### 列構成（15列）

| 列 | 項目名 | 用途 |
|---|---|---|
| A | 請求アカウント | ファイル・取込単位の識別 |
| B | 請求アカウント名称 | 参考表示 |
| C | 請求月 | 請求月（利用月+1ヶ月） |
| D | 利用月 | 対象年月の判定 |
| F | ご利用番号 | 番号マスタとの照合（表番号 or 裏番号） |
| **H** | **通話種別名称** | **課金4パターンへの分類** |
| **N** | **通話時間** | **秒数（タリフ計算の元値）** |
| **O** | **通話料金** | **ナビ（金額課金）の元値** |
| その他 | 部署名・関連契約番号・着信番号・通話開始年月日・通話開始時間・通話先電話番号・通話先地域 | 明細参照用に保持 |

### 取込ルール（重複・差分）

| ケース | 扱い |
|---|---|
| まったく同じファイルを再アップロード | **スキップ**（取込せず画面にスキップした旨を表示） |
| 同一の請求アカウント×利用月で内容が異なるファイル | **差分として追記取込**（既存データは消さず、追加分を加算して再集計） |

- 判定方法：ファイル内容のハッシュ値を取込履歴に保存し、一致した場合はスキップ
- 差分取込後は該当取引先×利用月の金額を自動で再計算する

## 7. 課金計算ルール

### 7-1. 通話種別の分類（4パターン）

H列「通話種別名称」で以下に分類する。

| パターン | 通話種別名称（H列） | 計算式 |
|---|---|---|
| ① 固定 | 国内通話料(固定宛) / 国内通話料(IP宛) / フリーコール通話料(固定着) | 通話時間（秒）× タリフ |
| ② 携帯 | 国内通話料(携帯宛) / フリーコール通話料(携帯着) | 通話時間（秒）× タリフ |
| ③ ナビ（秒課金） | ナビダイヤル | 通話時間（秒）× タリフ |
| ④ ナビ（金額課金） | その他料金 | 通話料金（O列）× タリフ |

※ ③と④は**合算**してナビ分の金額とする。

### 7-2. タリフ（単価）

| パターン | デフォルトタリフ |
|---|---|
| ① 固定 | 0.06 円/秒 |
| ② 携帯 | 0.25 円/秒 |
| ③ ナビ（秒課金） | 1.2 円/秒 |
| ④ ナビ（金額課金） | 10.5 倍（O列金額に乗算） |

- デフォルトタリフはシステム設定として保持し、**修正可能**とする
- **取引先単位で4パターンそれぞれ上書き可能**（未設定の場合はデフォルトを適用）

### 7-3. 集計・端数処理

| 項目 | ルール |
|---|---|
| 集計単位 | **取引先（会社）ごと**に全通話を合算 |
| 端数処理 | **SF商品単位で切り上げ（計2回）**：①固定分・②携帯＋ナビ分それぞれの合計金額に対して小数点以下を切り上げ |
| 総合計 | 切り上げ後の①＋②の合算値 |
| 番号単位 | 番号ごとの内訳は小数のまま保持（明細確認用） |

## 8. 番号マスタ（表番号・裏番号）

### 仕様

- 1取引先に対して**複数の電話番号**を登録できる
- 各番号に**裏番号（フリーダイヤル）を1つ**紐付けられる
- CDRの「ご利用番号」（F列）が**裏番号で記載されていても、表番号と同一取引先として名寄せ**する

### 照合ロジック

```
CSVのご利用番号
  → 番号マスタの表番号と照合 → 一致すれば取引先確定
  → 一致しない場合、裏番号と照合 → 一致すれば表番号の取引先に紐付け
  → どちらとも不一致 → 未紐付けとして取込結果に警告表示
```

## 9. 請求日ルール

携帯回線（利用月+2ヶ月）とは**異なる**ため注意。

| 項目 | 内容 |
|---|---|
| ルール | 利用月の **1ヶ月後** が請求月（CSVのC列と一致） |
| 請求開始日 | 請求月の1日 |
| 請求終了日 | 請求月の末日 |

## 10. Salesforce登録内容

取引先ごとに**2商品**をOpportunityLineItemとして登録する。

| # | 商品コード | 商品名 | 対象金額 |
|---|---|---|---|
| ① | `CC_01` | IP回線通話料_国内固定番号宛 | 固定分（パターン①） |
| ② | `CC_02` | IP回線通話料_国内携帯番号宛 | 携帯＋ナビ分（パターン②＋③＋④） |

| SFフィールド | 値 |
|---|---|
| 商品コード | `CC_01` / `CC_02`（固定） |
| 商品名 | 上記2種（固定） |
| 販売価格 | 各商品の合計金額 |
| 数量 | 1（固定） |
| 請求開始日 | 利用月+1ヶ月の1日 |
| 請求終了日 | 利用月+1ヶ月の末日 |
| 商談 | `tenants.sfOpportunityId`（既存流用） |

## 11. 画面構成

**方針：携帯回線の画面構成をそのまま踏襲し、文言をIP回線用に修正する。**  
現行のIP回線タブ・メニューは削除し、以下に置き換える。

### 11-1. ダッシュボード（`/` IP回線タブ）

携帯回線タブと同一構成に刷新。

| 要素 | 内容 |
|---|---|
| SF送信待ち一覧 | IP回線の未送信取引先一覧 |
| IP回線契約状況 | 契約中の取引先・番号数サマリ |

※ 上部共通カード（有効テナント・SF送信待ち合計）は現行のまま。IP側の件数算出ロジックのみ新方式に差し替え。

### 11-2. インポート（`/import`）

| 項目 | 内容 |
|---|---|
| AdjustOne CSV | **削除** |
| ProDelight CSV | **削除** |
| **CDR CSV** | **新規追加（複数ファイル同時アップロード対応）** |
| SoftBank ファイル | 既存のまま（携帯回線） |

### 11-3. IP回線マスタ（新規：`/ip/master`）

携帯の回線マスタ（`/mobile/master`）と同構成。

- 電話番号の新規登録（個別フォーム）＋ **裏番号（フリーダイヤル）の紐付け欄**
- CSV一括インポート（テンプレートダウンロード付き）
- 取引先との紐付け編集
- 契約ステータス管理（契約中 / 解約済）

### 11-4. IP回線 月次請求管理（新規：`/ip/billing/[yearMonth]`）

携帯の月次請求管理と同構成。

- 上部サマリカード（SF送信待ち / 総通話料）
- 取引先ごとの一覧（固定分・携帯＋ナビ分・合計・ステータス）
- 一括 / 選択 / 個別SF送信
- CSVエクスポート

### 11-5. 契約番号一覧（新規：`/ip/numbers`）

携帯の契約端末一覧（`/mobile/devices`）に相当。

- 月ナビゲーション（右上 `< 年月 >` 形式）
- 番号・裏番号・取引先・通話種別ごとの内訳金額・合計
- テキスト検索・CSVエクスポート

### 11-6. タリフ設定（新規：`/ip/tariffs`）

- デフォルトタリフ4種の表示・編集
- 取引先別タリフの一覧・上書き設定・解除（解除でデフォルトに戻る）

## 12. 既存機能の廃止

| 廃止対象 | 内容 |
|---|---|
| AdjustOne / ProDelight CSV取込 | インポート画面から削除 |
| パック管理・超過料金計算 | 画面・ロジックとも廃止 |
| 現行IP回線タブ・メニュー | 新構成に置き換え |

※ 旧テーブル（`channel_groups` / `tenant_packs` / `monthly_usages` 等）は**削除**する。ただし `phone_numbers` などの電話番号↔取引先データは Phase E の初期データ移行の元データとなるため、**移行完了後に削除**する。

### 旧テーブルのデータ確認手順

削除前に、旧テーブルに実データが入っているかを確認する。プロジェクトルートで以下を実行（PowerShell）。

```powershell
node -e "const db=require('better-sqlite3')('lime.db');['billing_accounts','channel_groups','phone_numbers','tenant_assignments','tenant_packs','monthly_usages','call_logs'].forEach(t=>{try{console.log(t+': '+db.prepare('SELECT COUNT(*) c FROM '+t).get().c+'件')}catch(e){console.log(t+': テーブルなし')}})"
```

**結果による判断基準**

| 結果 | 対応 |
|---|---|
| 全テーブル0件 | Phase Eを待たず、Phase D（旧機能廃止）の時点でテーブルごと削除してよい |
| `phone_numbers` にデータあり | 番号マスタ（`ip_numbers`）への移行元として使用するため、Phase Eの移行完了後に削除する |

## 13. DBスキーマ設計（新規追加）

```
ip_numbers（IP回線番号マスタ）
  id, tenant_id, phone_number,
  sub_number,          -- 裏番号（フリーダイヤル）NULL可
  status,              -- 契約中 / 解約済
  notes, created_at, updated_at

ip_tariffs（タリフ設定：取引先別上書き）
  id, tenant_id,       -- NULL = デフォルトタリフ
  fixed_rate,          -- ①固定 円/秒（デフォルト 0.06）
  mobile_rate,         -- ②携帯 円/秒（デフォルト 0.25）
  navi_sec_rate,       -- ③ナビ秒課金 円/秒（デフォルト 1.2）
  navi_amount_rate,    -- ④ナビ金額課金 倍率（デフォルト 10.5）
  created_at, updated_at

ip_usages（IP月次通話料）
  id, tenant_id, year_month,
  fixed_amount,        -- 固定分（SF商品①・切り上げ後）
  mobile_navi_amount,  -- 携帯＋ナビ分（SF商品②・切り上げ後）
  total_amount,        -- ①＋②の総合計
  sf_status, sf_sent_at, sf_error_message,
  imported_at, created_at, updated_at

ip_usage_details（番号×通話種別の内訳）
  id, ip_usage_id, tenant_id, phone_number,
  call_category,       -- 固定 / 携帯 / ナビ秒 / ナビ金額
  call_type_name,      -- H列の通話種別名称
  total_seconds,       -- 通話時間合計
  source_amount,       -- O列金額合計（ナビ金額用）
  computed_amount,     -- タリフ計算後金額（小数のまま）
  year_month, created_at

ip_import_files（取込履歴・重複判定）
  id, file_name, file_hash,
  billing_account, year_month,
  row_count, imported_at
```
